> [!abstract] Обзор операционно-технического регламента
> Настоящий регламент определяет архитектурные, протокольные и технологические требования по замещению оборудования сетей радиодоступа ([[RAN]]) западных вендоров ([[Ericsson]], [[Nokia]]) на китайские платформы ([[Huawei]], [[ZTE]]), а также на OEM/ODM-решения локальной сборки. В документе детально проанализированы системные барьеры на всех уровнях готовности технологий — от фундаментальных компонентов и физики полупроводников (**TRL 1–6**) до интегрированных промышленных комплексов и коммерческой эксплуатации (**TRL 7–9**).

## 1. Межвендорская интеграция и протокольные барьеры (TRL 7–9)

При замещении базовых станций в действующей гетерогенной сети главной проблемой является нарушение совместимости на стыках оборудования различных производителей ([[Interoperability]]).

```
┌────────────────────────┐          Proprietary X2/Xn IE         ┌────────────────────────┐
│   eNodeB / gNodeB      │ <==================================> │   eNodeB / gNodeB      │
│   (Ericsson / Nokia)   │    [Degradation: Drop Rate +3-7%]    │     (Huawei / ZTE)     │
└────────────────────────┘                                      └────────────────────────┘
            │                                                               │
            │ Proprietary CPRI / eCPRI                                      │ Proprietary CPRI / eCPRI
            ▼                                                               ▼
┌────────────────────────┐                                      ┌────────────────────────┐
│   RRU/AAU Ericsson     │                                      │     RRU/AAU Huawei     │
└────────────────────────┘                                      └────────────────────────┘
```

### 1.1. Асимметрия стандартов [[3GPP]] и проприетарные расширения

Хотя ключевые интерфейсы стандартизированы спецификациями [[3GPP]] (TS 36.423 для X2, TS 38.423 для Xn, TS 38.473 для F1), вендоры первого эшелона внедряют в служебный трафик закрытые информационные элементы (*Proprietary Information Elements, IE*):

* **Межсетевой хэнд-овер ([[Handover]]):** Проприетарные структуры данных в контейнерах `HandoverRequest` передают закрытые метрики управления радиоресурсами ([[RRM]]), параметры профилей лучей в [[Massive MIMO]] и нестандартные критерии оценки качества сигнала ($RSRP/RSRQ/SINR$), что блокирует бесшовную передачу сессии абонента между БС разных производителей.
* **Координированное гашение помех ([[ICIC]] / [[eICIC]] / [[CoMP]]):** Алгоритмы совместной обработки сигналов несколькими БС требуют обмена данными в реальном времени с задержкой $\le 1\text{ ms}$. Несовместимость закрытых матриц канального состояния ($CSI$) делает работу CoMP межвендорски нереализуемой.
* **Агрегация несущих частот ([[Carrier Aggregation]]):** Назначение ведомых сот (*Secondary Cells, SCells*) от другого вендора блокируется на уровне протокола RRC (Radio Resource Control) из-за отсутствия общепринятых спецификаций синхронизации буферов L2-уровня.

### 1.2. CPRI / eCPRI и проблемы точной синхронизации

Соединение между модулем обработки базовой полосы ([[BBU]]) и радиомодулем ([[RRU]] / AAU) использует интерфейсы [[CPRI]] или [[eCPRI]]:

1. **CPRI (Option 3..10):** Из-за отсутствия полной жесткой стандартизации вендоры кодируют управляющие слова (*Control & Management words*) по закрытым алгоритмам. Подключение RRU [[Ericsson]] к BBU [[Huawei]] технически невозможно.
2. **eCPRI (Split Option 7-2x):** eCPRI переносит трафик поверх Ethernet (IEEE 802.3). Однако структура сжатия IQ-данных (Block Floating Point, BFP) и алгоритмы компенсации фазовых дрожаний различаются.
3. **Требования к синхронизации:** Для сетей TDD и Massive MIMO фазовая погрешность между соседними антенными решетками не должна превышать **$\pm 1.5\ \mu\text{s}$**. Для этого необходима сквозная поддержка профилей [[IEEE 1588v2]] / PTP (G.8275.1 Telecom Profile) и [[SyncE]] на всех промежуточных коммутаторах [[Backhaul]] / [[Front-haul]].

> [!warning] Ограничения межвендорского взаимодействия
> Прямое стыкование радиооборудования [[Ericsson]]/[[Nokia]] и [[Huawei]]/[[ZTE]] в рамках одного кластера хэнд-овера без физического территориального разделения приводит к росту срывов соединений (**Drop Rate**) на **3–7%**, увеличению задержек (**Latency**) и падению средней пропускной способности абонентов до **30%**.

## 2. Глубокий анализ компонентной базы и TRL-барьеров локализации

Для создания суверенного или локализованного оборудования (OEM/ODM) требуется преодоление технологических барьеров на каждом уровне TRL.

```
┌──────────────────────────────────────────────────────────────────────────────────┐
│                         ТЕХНОЛОГИЧЕСКИЙ СТЕК БАЗОВОЙ СТАНЦИИ                      │
├───────────────────────────────┬──────────────────────────────────────────────────┤
│ Уровень радиосигналов (RRU)   │ GaN-on-SiC HEMTs, BAW/SAW Фильтры, RF-DAC/ADC    │ ◄── TRL 1–4 (Критический дефицит)
├───────────────────────────────┼──────────────────────────────────────────────────┤
│ Уровень цифровой обработки    │ FPGA, DSP, ASIC (L1/L2 Ускорители), SoC           │ ◄── TRL 3–5 (Silicon Bottleneck)
├───────────────────────────────┼──────────────────────────────────────────────────┤
│ Печатные платы и SMT-монтаж   │ HF-ламинаты (Rogers), 16-24 слоя, BGA 0.3 мм      │ ◄── TRL 6–7 (Зависимость от сырья)
├───────────────────────────────┼──────────────────────────────────────────────────┤
│ Системное ПО и Протоколы      │ Стек L1/L2/L3, DPD-математика, HAL-абстракция    │ ◄── TRL 5–8 (Проблема IP / "Black Box")
└───────────────────────────────┴──────────────────────────────────────────────────┘
```

### 2.1. Детализация цепочки готовности технологий (TRL 1 ➔ TRL 9)

#### TRL 1–3: Фундаментальные исследования и физические принципы
* **Полупроводники ВЧ-тракта ([[GaN Semiconductors|GaN-on-SiC]]):** Производство транзисторов с высокой подвижностью электронов (HEMT) требует гетероэпитаксиального выращивания слоев нитрида галлия на подложках карбида кремния. В РФ отсутствуют промышленные установки MOCVD (металлоорганическая газофазная эпитаксия) нужной производительности для массового выпуска транзисторов диапазона $2.6–4.9\text{ GHz}$ с КПД (PAE) $>50\%$.
* **Акустические фильтры ([[BAW Filters|BAW]] / SAW / FBAR):** Для разделения близкорасположенных полос частот (например, Band 3 и Band 7, а также n77/n78/n79) необходимы тонкопленочные пьезоэлектрические резонаторы на базе AlN/AlScN. Технологии их проектирования и MEMS-фабрикации в РФ находятся на этапе лабораторных образцов (**TRL 2–3**).

#### TRL 4–5: Лабораторные прототипы и цифровые интегральные схемы (Silicon Bottleneck)
* **Цифровая обработка базовой полосы ([[BBU]]):** Выполнение операций преобразония Фурье (FFT/IFFT), кодирования/декодирования LDPC и Polar-кодов требует узкоспециализированных [[ASIC]] или мощных [[FPGA]] (Xilinx UltraScale+, Altera Stratix 10, либо китайских PangoMicro Titan-2 / Anlogic).
* **Математика Цифрового Предискажения ([[DPD]]):** Силовые усилители (PA) работают в нелинейном режиме. Для компенсации искажений применяются алгоритмы DPD на основе полиномиальных рядов Вольтерра:
  $$y(n) = \sum_{k=0}^{K-1} \sum_{m=0}^{M-1} a_{km} \cdot x(n-m) \cdot |x(n-m)|^k$$
  Отсутствие отечественных математических ядер DPD и аппаратных ускорителей L1-уровня сдерживает создание собственных RRU на уровне **TRL 4**.
* **Фабрикация (Foundry):** Требуемые технологические нормы для ASIC базовой полосы составлять должны **7–16 нм**. Доступные отечественные мощности (Микрон) ограничены **90–65 нм**, что ведет к неприемлемому энергопотреблению и габаритам оборудования при попытке реализации L1-стека.

#### TRL 6–8: Отработка производства и пилотные партии
* **Высокочастотные печатные платы:** Производство платных модулей требует применения ламинатов с низким коэффициентом диэлектрических потерь ($\tan \delta < 0.002$) типа Rogers RO4350B / Isola IS680. Отечественные аналоги находятся в стадии опытного производства (**TRL 5–6**), сырьевая база (специализированные стеклоткани и связующие смолы) импортируется.
* **[[SMT]]-монтаж:** Автоматизированные линии поверхностного монтажа в РФ ([[Аквариус]], [[YADRO]]) способны осуществлять монтаж BGA-компонентов с шагом до 0.3 мм и компонентов 0201. Однако высокий процент брака при монтаже 24-слойных высокочастотных плат снижает экономическую целесообразность CKD-сборки без китайского инжинирингового сопровождения.

## 3. Влияние программы «Made in China 2025» и риски IP-зависимости

Программа правительств КНР **«Made in China 2025»** нацелена на достижение полной технологической независимости собственного рынка. Это создает жесткий конфликт интересов при попытках локализации оборудования в РФ.

```
+-----------------------------------------------------------------------+
|                       «Made in China 2025»                            |
|    Приоритет: Полный суверенитет КНР по всей цепочке стоимости       |
+-----------------------------------------------------------------------+
                                    │
       ┌────────────────────────────┴────────────────────────────┐
       ▼                                                         ▼
[Внутренний рынок КНР]                                [Внешняя экспансия]
- Собственная компонентная база                      - Экспорт готовых изделий (High margin)
- Стандартизация под нац. операторов                 - Блокировка передачи исходных кодов (IP)
- Экономия на масштабе (Scale economy)              - Риск вторичных санкций (OFAC/BIS)
                                                                 │
                                                                 ▼
                                                    [РФ: Вызовы локализации]
                                                    - Синдром "Black Box" (Закрытый бинарник)
                                                    - Высокая премия за риск (+30...50%)
                                                    - Угроза дистанционной блокировки
```

> [!danger] Зависимость от закрытого IP ("Black Box Syndrome")
> При соглашении об OEM/ODM-сборке китайские вендоры передают конструкторскую документацию на корпус и схемы разводки плат, но оставляют за собой:
> 1. RTL-описания ASIC и прошивки [[FPGA]].
> 2. Исходный код уровня [[L1 Layer|L1]] (PHY) и микрокод DSP.
> 3. Доступ к уровню абстракции аппаратного обеспечения ([[HAL Layer]]).
> 
> Это оставляет локализованные БС полностью зависимыми от китайского обновления ПО и не позволяет внедрять суверенные алгоритмы защиты.

## 4. Требования регуляторов: Частоты, Шифрование и [[СОРМ-3]]

Процесс локализации и параллельного импорта сталкивается с нормативными барьерами регулирующих органов РФ ([[ГКРЧ]], ФСБ, Минцифры).

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    Блок-схема регуляторной адаптации                    │
└─────────────────────────────────────────────────────────────────────────┘
                                     │
      ┌──────────────────────────────┼──────────────────────────────┐
      ▼                              ▼                              ▼
[Сетка частот ГКРЧ]       [Требования СОРМ-3]         [ГОСТ-Шифрование]
• Перепрошивка RFIC       • Съём трафика N3/N4        • Отсутствие HW-ускорения
• Частоты: Band 1,3,7,20  • Интеграция с ISG          • Вынос на внешний IPsec
• 5G: Band n79 (4.8-4.9)  • Нормативы № 86 / № 571   • Задержка < 1 ms (Strict)
```

### 4.1. Частотный план и перенастройка радиочастотных блоков ([[ГКРЧ]])
* Оборудование, ввозимое по схеме параллельного импорта из КНР, настроено под китайские диапазоны (например, Band 39/40/41 или 5G n77/n78).
* Использование 5G в РФ в диапазоне n78 ($3.4–3.8\text{ GHz}$) ограничено регулятором. Основным целевым диапазоном назначен **n79 ($4.4–4.99\text{ GHz}$)**.
* Требуется глубокая модификация радиотракта (RF Frontend): замена полосовых фильтров, перенастройка трансиверов (типа AD9371) и доработка антенных матриц, что на уровне **TRL 7** требует полной пересертификации оборудования.

### 4.2. Безопасность и криптографическая защита ([[ГОСТ 34.12-2015]])
1. **Невозможность аппаратно-программной интеграции ГОСТ:**
   3GPP-стандарты используют алгоритмы шифрования EEA1/EIA1 (SNOW 3G), EEA2/EIA2 (AES-128), EEA3/EIA3 (ZUC). Внедрение отечественных алгоритмов **[[ГОСТ 34.12-2015]] («Кузнечик» / «Магма»)** непосредственно в стеки BBU невозможно из-за закрытости чипсетов и отсутствия соответствующего instruction set в китайских DSP.
2. **Архитектурный выход (Вынос на внешний уровень):**
   Единственным легитимным решением является вынос функции ГОСТ-шифрования на внешние программно-аппаратные комплексы (криптошлюзы) на границе транспортной сети ([[Backhaul]]):
   
$$\text{eNodeB/gNodeB} \xrightarrow{\text{Plain IP/eCPRI}} \left[ \text{ГОСТ IPsec Gateway} \right] \xrightarrow{\text{Encrypted Tunnel}} \left[ \text{Core Network / EPC / 5GC} \right]$$

3. **Интеграция с [[СОРМ-3]]:**
   Необходимо обеспечение съема трафика Control Plane и User Plane в соответствии с требованиями ПП РФ № 86 и № 571. В закрытых китайских архитектурах требуется установка дополнительных зондов на интерфейсах N2/N3 (5G) или S1-MME/S1-U (LTE).

## 6. Пошаговый алгоритм перехода на vRAN / OpenRAN (TRL 5 ➔ TRL 8)

Для преодоления зависимости от монополии вендоров утверждается следующий операционный регламент внедрения декомпозированной архитектуры [[OpenRAN]].

```
┌───────────────────────────────────────────────────────────────────────────────────┐
│                    ПЛАН МИГРАЦИИ НА ОТКРЫТУЮ АРХИТЕКТУРУ                          │
└───────────────────────────────────────────────────────────────────────────────────┘
                                          │
 ┌────────────────────────────────────────┼────────────────────────────────────────┐
 ▼                                        ▼                                        ▼
[ФАЗА 1: Монокластеризация]      [ФАЗА 2: Внешний Security-Слой]          [ФАЗА 3: O-RAN Развертывание]
• Зонирование сети               • Вынос ГОСТ-шифрования                  • Разделение CU / DU / RU
• Высвобождение европейского ЗИП • Установка СОРМ-3 зондов               • Использование COTS-серверов
• Изоляция закрытых БС КНР       • Изоляция O&M каналов                  • O-RAN Fronthaul Split 7.2x
```

### 6.1. Техническая реализация Фазы 3 (Архитектура OpenRAN)

```
┌────────────────────────────────────────────────────────────────────────────────┐
│                                O-RAN АРХИТЕКТУРА                               │
├───────────────────────────────┬────────────────────────────────────────────────┤
│ O-RU (Radio Unit)             │ Прием/передача RF, Low-PHY (FFT/IFFT, PRACH)   │
├───────────────────────────────┼────────────────────────────────────────────────┤
│ O-DU (Distributed Unit)       │ High-PHY (LDPC), MAC, RLC (COTS + Accelerator) │
├───────────────────────────────┼────────────────────────────────────────────────┤
│ O-CU (Centralized Unit)       │ PDCP, SDAP, RRC (COTS x86/ARM, Cloud Native)   │
└───────────────────────────────┴────────────────────────────────────────────────┘
```

1. **Разделение интерфейсов (O-RAN Option 7-2x):**
   * **C-Plane (Control):** Передача команд управления лучами (Beamforming) и секциями кадра.
   * **U-Plane (User):** Передача сжатых IQ-данных с использованием метода Block Floating Point (BFP) с разрядностью 9–12 бит.
   * **S-Plane (Synchronization):** Синхронизация O-RU и O-DU по протоколу PTP (IEEE 1588v2) с профилем G.8275.1 (погрешность Alignment Error $< 130\text{ ns}$).
   * **M-Plane (Management):** Управление конфигурацией радиомодулей по протоколу NETCONF с использованием YANG-моделей.

2. **Вычислительная платформа O-DU/O-CU:**
   * Базируется на [[COTS]]-серверах с процессорами x86 (Intel Xeon / AMD EPYC) или ARM (Neoverse).
   * Использование специализированных фреймворков ускорения обработки сетевых пакетов: **DPDK (Data Plane Development Kit)** и **SR-IOV** для минимизации задержек ОС Linux (`PREEMPT_RT` kernel).
   * Аппаратное ускорение декодирования LDPC на L1-уровне реализуется через плату ускорения (Inline / Lookaside accelerator) на базе FPGA или ASIC.

## 7. Практические кейсы и задачи самопроверки

### Кейс 1: Авария межкластерного хэнд-овера и фазовая десинхронизация
> **Сценарий:** На границе раздела двух моновендорских кластеров (Кластер А: [[Ericsson]], Кластер Б: [[Huawei]]) фиксируется массовый срыв вызовов (Drop Rate достигает 12%) при передаче абонентов 5G SA. Анализатор протоколов показывает фазовое расхождение между БС соседей в $3.2\ \mu\text{s}$, а также сброс контейнера `HandoverRequest` со статусом `Unrecognised IE`.
> 
> **Задание:** Определить первопричину сбоя и предложить инженерное решение.

> [!check]- Решение и разбор кейса
> **Первопричина:** 
> 1. Превышение порога фазового расхождения ($3.2\ \mu\text{s} > 1.5\ \mu\text{s}$) вызвано некорректным профилем PTP на граничном коммутаторе транспортной сети.
> 2. Сброс `HandoverRequest` вызван передачей закрытого проприетарного IE Ericsson, который не поддерживается стеком Huawei XnAP.
> 
> **Пошаговое решение:**
> 1. Настроить на транспортном оборудовании профиль [[IEEE 1588v2]] (G.8275.1) с гарантией компенсации задержки для снижения фазовой погрешности до $< 1.0\ \mu\text{s}$.
> 2. Перевести процедуру Handover между кластерами с интерфейса **Xn** на межсетевой интерфейс **NG** (через ядро [[5GC]]), принудительно активировав трансляцию контейнеров RRC на стороне AMF (Core Network).

### Кейс 2: Интеграция ГОСТ-шифрования в OEM-платформу TRL 7
> **Сценарий:** Отечественный производитель собирает БС по ODM-лицензии из КНР. Для включения в реестр ТОРП и соблюдения требований ФСБ необходимо обеспечить шифрование управляющего трафика и трафика пользователей по стандарту [[ГОСТ 34.12-2015]] («Кузнечик»). ODM-разработчик из КНР категорически отказывается предоставить исходный код L1/L2 ПО BBU и структуры FPGA.
> 
> **Задание:** Разработать архитектурное решение, позволяющее пройти сертификацию без нарушения условий ODM-поставщика.

> [!check]- Решение и разбор кейса
> **Ошибочные варианты:** Попытки реверс-инжиниринга прошивки BBU или внесения изменений в бинарные файлы приведут к снятию оборудования с гарантии ODM-поставщика и неработоспособности L1-стека real-time обработки.
> 
> **Корректное решение:**
> 1. Оставить стек BBU без изменений в части 3GPP-криптографии (AES/ZUC).
> 2. Внедрить внешнюю двухузловую схему защиты: на границе S1-U/N3 и S1-MME/N2 установить дублированные внешние криптошлюзы (ГОСТ IPsec Gateway).
> 3. Изолировать сегмент BBU и радиомодулей в незащищенной технологической зоне (Zero Trust Zone), зашифровав 100% выходящего трафика Backhaul в туннель ГОСТ IPsec с аппаратной реализацией на отечественной НИИ-базе.
> 4. Согласовать с регулятором частное техническое решение на базе комплексного узла связи.
