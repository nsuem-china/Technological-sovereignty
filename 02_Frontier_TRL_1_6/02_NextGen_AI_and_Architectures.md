## 1. Стратегический манифест Консорциума

Развитие традиционной фон-неймановской парадигмы уперлось в физические и геополитические барьеры. Попытка копирования монолитных гига-GPGPU на экстремально тонких техпроцессах ($3\text{нм}$–$2\text{нм}$) в условиях технологической изоляции стратегически тупиковая. Консорциум реализует концепцию **«Архитектурного Маневра» (Architectural Leapfrogging)**.

```
                  ┌──────────────────────────────────────────┐
                  │   ЦЕЛЬ: Выход на TRL 5-6 к 2028 году     │
                  └─────────────────────┬────────────────────┘
                                        │
         ┌──────────────────────────────┴──────────────────────────────┐
         ▼                                                             ▼
┌───────────────────────────────┐                             ┌───────────────────────────────┐
│     АППАРАТНЫЙ ВЕКТОР        │                             │      ПРОГРАММНЫЙ ВЕКТОР       │
├───────────────────────────────┤                             ├───────────────────────────────┤
│ • [[Compute-in-Memory]] (CiM) │                             │ • Компиляция через [[MLIR]]   │
│ • [[RISC-V-Vector-Extensions]]│                             │ • Ядра на [[Triton-Compiler]] │
│ • [[Chiplet-Design]] (28нм)   │                             │ • Фреймворки [[MindSpore]]    │
└───────────────────────────────┘                             └───────────────────────────────┘
```

### 1.1. Физика ограничений и отказ от Фон-Неймановской модели
В классических вычислителях энергический бюджет расходуется не на математические операции, а на перемещение данных через иерархию памяти (узкое место — [Memory-Wall](../Memory-Wall.md)).

$$E_{\text{total}} = E_{\text{compute}} + E_{\text{interconnect}} + E_{\text{DRAM}}$$

При техпроцессах $<5\text{нм}$ операция умножения c накоплением (MAC) в точности FP16 требует около $0.4\text{ pJ}$, в то время как выборка операндов из внешнего стека [HBM3e](../HBM3e.md) расходует $20\text{–}30\text{ pJ/bit}$. 

{% hint style="warning" %}
**Физический и геополитический тупик**
1. **Литографический барьер:** Невозможность импорта EUV-сканеров [ASML-EUV](../ASML-EUV.md) делает недостижимой плотность транзисторов на уровне $>150\text{ млн/мм}^2$.
2. **Память:** Отсутствие доступа к стекам [HBM3e](../HBM3e.md) и контроллерам [CoWoS](../CoWoS.md) блокирует создание классических шин с пропускной способностью $>3\text{ ТБ/с}$.
3. **Энергетический предел:** Охлаждение монолитных кристаллов площадью $>800\text{ мм}^2$ с TDP $>1000\text{ Вт}$ требует жидкостного охлаждения на пределе фазового перехода.
{% endhint %}

Стратегический ответ — замена плотности транзисторов **пространственной интеграцией вычислений и памяти (Compute-in-Memory)** на зрелых технологических узлах ($28\text{нм}$–$14\text{нм}$) с использованием 2.5D/3D-компоновки [Chiplet-Design](../Chiplet-Design.md).

## 2. Глубокая декомпозиция архитектурного стека (TRL 1–6)

Для достижения функциональной независимости стек вычислений разбивается на четыре фундаментальных слоя.

```
[Уровень приложений: [[MoE-Architecture]], LLM, [[Spiking-Neural-Networks]]]
                                     │
                                     ▼
[Компиляторный слой: [[Triton-Compiler]] ➔ Dialects [[MLIR]] (`#cim`, `#rvv`)]
                                     │
                                     ▼
[Слой аппаратных абстракций (HAL): Суверенный CAPI / [[CANN]] Runtime]
                                     │
                                     ▼
[Аппаратный слой: [[RISC-V-Vector-Extensions]] Cores + [[SRAM-dIMC]] / [[ReRAM]] Crossbars]
```

### 2.1. Аппаратный слой (Hardware & Silicon Infrastructure)

#### 2.1.1. Вычислительное управляющее ядро (Host & Vector Execution)
Основано на открытой архитектуре [RISC-V](../RISC-V.md) (профиль `RVA22`/`RVA23`).
*   **Векторный блок:** Реализация стандартизированного расширения `RVV 1.0` (Vector Extension) с шириной вектора $VLEN = 512\text{–}2048\text{ бит}$.
*   **Кастомные матричные расширения (`X-Matrix` ISA):** Специализированные инструкции для управления асинхронными CiM-кроссбарами (инициализация весов, конфигурирование АЦП/ЦАП, триггеры импульсов стробирования).

#### 2.1.2. Не-фон-неймановский ускоритель (Compute-in-Memory Subsystem)
Использует гибридную технологию, разделенную по типам задач:
*   **Цифровой CiM ([SRAM-dIMC](../SRAM-dIMC.md)):** Ячейки $8\text{T}/10\text{T}$ SRAM для высокоточных операций (Attention heads, генерация токенов). Каждая ячейка содержит локальную логику NOR/XOR, позволяющую выполнять векторно-матричное умножение (GEMM) внутри массива без чтения строк на внешнюю шину.
*   **Аналоговый CiM ([ReRAM](../ReRAM.md) Crossbars):** Массивы резистивной памяти на основе оксидов металлов ($\text{HfO}_x/\text{TaO}_x$) для проекций высокой размерности в [MoE-Architecture](../MoE-Architecture.md) и спайковых сетей [Spiking-Neural-Networks](../Spiking-Neural-Networks.md). Вычисления выполняются на основе законов Кирхгофа и Ома ($I = \sum V_i \cdot G_{ij}$).

#### 2.1.3. Интерконнект и межкристальная интеграция (Interconnect & Packaging)
*   **Топология:** 2.5D-компоновка на кремниевом интерпозере (Silicon Interposer) или RDL-органическом субстрате.
*   **Физический интерфейс (D2D):** Открытый стандарт [UCIe](../UCIe.md) (Universal Chiplet Interconnect Express) или [BoW](../BoW.md) (Bunch of Wires) на зрелых узлах $28\text{нм}$.
*   **Пропускная способность:** Плотность контактов microbumps с шагом $40\text{–}55\text{ мкм}$, обеспечивающая $>2\text{ ТБ/с/мм}$ фронта кристалла при задержках $<2\text{ нс}$.

```
 ┌────────────────────────────────────────────────────────────────────────┐
 │                      2.5D CHIPLET ASSEMBLY                             │
 │                                                                        │
 │   ┌─────────────────┐    UCIe Bus    ┌─────────────────────────────┐   │
 │   │  RISC-V Host    │◄──────────────►│    SRAM-dIMC / ReRAM        │   │
 │   │  Control Die    │                │    Compute-in-Memory        │   │
 │   └────────┬────────┘                └──────────────┬──────────────┘   │
 │            │                                        │                  │
 │   ─────────┴────────────────────────────────────────┴───────────────   │
 │                     SILICON INTERPOSER (28nm Node)                     │
 └────────────────────────────────────────────────────────────────────────┘
```

### 2.2. Программный стек и ликвидация CUDA-зависимости

Слом монополии NVIDIA достигается отходом от императивного написания ядер на CUDA C++ в пользу декларативных компиляторных абстракций.

```
       [PyTorch / MindSpore Model]
                    │
                    ▼
          [Triton Compiler JIT]
                    │
                    ▼
         [MLIR: High-Level Dialect]
         (tosa.matmul / linalg.generic)
                    │
                    ▼ (Pass Pipeline)
         [MLIR: Custom Target Dialects]
       ┌────────────┴────────────┐
       ▼                         ▼
[`#rvv` Dialect]         [`#cim` Dialect]
 (RVV Vectorization)     (SRAM/ReRAM Config)
       │                         │
       ▼                         ▼
[LLVM CodeGen]           [CiM Register Mapper]
       │                         │
       └────────────┬────────────┘
                    ▼
        [Executable Binary File]
```

#### 2.2.1. Трансляция через [Triton-Compiler](../Triton-Compiler.md)
[Triton-Compiler](../Triton-Compiler.md) используется в качестве единого входного языка описания высокопроизводительных ИИ-операторов. Triton изолирует разработчика от особенностей аппаратной архитектуры, представляя программы в виде блочных операций над тензорами.

#### 2.2.2. Компиляторная инфрастуктура на базе [MLIR](../MLIR.md)
Процесс оптимизации и генерации кода проходит через цепочку промежуточных представлений (Dialects):
1.  **High-Level Dialects (`tosa`, `linalg`):** Графовые оптимизации, слияние операторов (Operator Fusion), квантование.
2.  **Mid-Level Custom Dialect (`#cim`):** Специализированный диалект Консорциума. Отвечает за:
    *   Разбиение тензоров на плитки (Tiling), совпадающие с физическим размером кроссбара (например, $256 \times 256$).
    *   Планирование циклов записи/выборки весов в [ReRAM](../ReRAM.md) / [SRAM-dIMC](../SRAM-dIMC.md).
    *   Управление режимами АЦП (разрядность $1\text{–}8\text{ бит}$).
3.  **Low-Level Dialect (`#rvv` + `LLVM IR`):** Генерация векторного кода для управляющего процессора [RISC-V](../RISC-V.md).

## 4. Дорожная карта TRL (2024–2028)

{% hint style="info" %}
**Системная эволюция от теории к железу**
Достижение TRL 6 требует жесткого соблюдения метрик валидации на каждом этапе. Любой сбой на этапе MPW (Multi-Project Wafer) компенсируется программной адаптацией в компиляторном слое.
{% endhint %}

```
2024 (TRL 2) ────────► 2025-2026 (TRL 3-4) ─────► 2027 (TRL 4-5) ─────► 2028 (TRL 5-6)
Архитектурный          FPGA-эмуляция и             First Tape-out          Интегрированный
дизайн стека           MPW тестовых узлов          Чиплета (28нм)          3D-модуль
```

### Этап 1: 2024 (TRL 2 — Формулирование концепции)
*   **Метрика:** Разработка и утверждение спецификации кастомного ISA-расширения `X-Matrix` для [RISC-V](../RISC-V.md).
*   **Результат:** Математическая модель системного симулятора (на базе Gem5/SystemC), демонстрирующая преимущество по энергоэффективности $>8\times$ над GPU NVIDIA H100 на задачах инференса [MoE-Architecture](../MoE-Architecture.md).

### Этап 2: 2025–2026 (TRL 3–4 — Лабораторные испытания компонентов)
*   **Метрика:** Прототипирование алгоритмов в кремнии через MPW (Multi-Project Wafer) на $28\text{нм}$.
*   **Результат:** 
    1. Тестовый кристалл [SRAM-dIMC](../SRAM-dIMC.md) ($4\text{ МБ}$) показал энергоэффективность $15\text{ TOPS/W}$ в точности INT8.
    2. Проведена эмуляция компилятора [Triton-Compiler](../Triton-Compiler.md) на FPGA-комплексе (Xilinx UltraScale+) с трансляцией графов через [MLIR](../MLIR.md).

### Этап 3: 2027 (TRL 5 — Валидация функционального чиплета)
*   **Метрика:** Изготовление полнофункциональных кристаллов: вычислительный чиплет [RISC-V-Vector-Extensions](../RISC-V-Vector-Extensions.md) + акселератор [ReRAM](../ReRAM.md).
*   **Результат:** Измерение параметров на тестовом стенде. Решение проблемы дрейфа сопротивления (Resistance Drift) с использованием алгоритмов динамической калибровки. Пропускная способность интерконнекта [UCIe](../UCIe.md) достигла $1.5\text{ ТБ/с}$.

### Этап 4: 2028 (TRL 6 — Демонстратор системы в релевантной среде)
*   **Метрика:** Финальный Tape-out 2.5D/3D чиплет-модуля. Запуск целевых нагрузок в условиях ЦОД.
*   **Результат:** Автономный запуск мультимодальной модели на $14\text{B}$ параметров (тип [MoE-Architecture](../MoE-Architecture.md)) при потребляемой мощности модуля $\le 120\text{ Вт}$. Отсутствие зависаний и системных ошибок в течение $720$ часов непрерывной работы.

## 6. Инжиниринговые кейсы и физико-технический разбор (Self-Assessment)

Ниже приведены реальные проблемы физического и программного уровня, возникающие при проектировании Не-Фон-Неймановских систем, и их инженерные решения.

### Кейс 1: Преодоление физического дрейфа проводимости (Resistance Drift) в [ReRAM](../ReRAM.md)

> **Сценарий:** При длительной работе ускорителя на базе аналогового [ReRAM](../ReRAM.md) температура кристалла поднялась до $+80^\circ\text{C}$. Из-за деградации состояния кислородных вакансий в слое $\text{HfO}_x$ проводимость ячеек изменилась по закону:
> 
> $$G(t) = G_0 \cdot \left(\frac{t}{t_0}\right)^{-\nu}$$
> 
> Это вызвало дрейф весов. Точность инференса модели [MoE-Architecture](../MoE-Architecture.md) упала на $22\%$.
> 
> **Вопрос:** Какое комплексное (аппаратно-программное) решение должно быть интегрировано в TRL 5 стек для компенсации этого эффекта без остановки вычислений?

{% hint style="success" %}
**Инженерное решение**
1. **Аппаратный уровень (Hybrid Compute Architecture):**
   * Критичные к деградации слои (Self-Attention Key/Query/Value матрицы) переносятся на цифровой **[SRAM-dIMC](../SRAM-dIMC.md)**, абсолютно устойчивый к температуре.
   * Аналоговый **[ReRAM](../ReRAM.md)** используется исключительно для избыточных слоев экспертов (Experts in MoE), где ошибка компенсируется алгоритмически.
2. **Уровень компилятора ([MLIR](../MLIR.md) Pass):**
   * Внедрение формата низкой точности **[MXFP6/MXFP4](../MXFP6/MXFP4.md)** с динамической масштабируемой точкой (Microscaling Formats).
3. **Слой схемотехники:**
   * Применение опорных ячеек-реплик (Dummy Reference Cells), физически находящихся на том же кроссбаре. Изменение тока на репликах автоматически корректирует напряжение опорного сигнала АЦП (Adaptive ADC Reference Tuning), компенсируя температурный дрейф $G(t)$ в реальном времени.
{% endhint %}

### Кейс 2: Трансляция сложных операторов Attention (MLA / FlashAttention) в код [RISC-V](../RISC-V.md) + CiM

> **Сценарий:** Внедряемая модель использует оператор [Multi-head-Latent-Attention](../Multi-head-Latent-Attention.md) (MLA), требующий частой смены размерностей тензоров и вычисления промежуточного Softmax. Попытка выполнить Softmax внутри аналогового кроссбара невозможно из-за экспоненциальной нелинейности.
> 
> **Вопрос:** Как настроить конвейер компиляции для эффективного распределения нагрузки между векторными ядрами и CiM-матрицами?

```
[Input Tensor] ──► [MLIR Tile Splitter]
                         │
        ┌────────────────┴────────────────┐
        ▼                                 ▼
(Linear GEMM Ops)                (Non-Linear Ops: Softmax)
        │                                 │
        ▼                                 ▼
[Compute-in-Memory]              [RISC-V Vector Unit]
(SRAM-dIMC Crossbar)             (RVV 1.0 Instructions)
        │                                 │
        └────────────────┬────────────────┘
                         ▼
             [Output Interposer Bus]
```

{% hint style="success" %}
**Инженерное решение**
1. **Разделение графа вычислений на уровне [MLIR](../MLIR.md) (`linalg-to-cim` pass):**
   * Операция декомпозируется: линейные матричные умножения $Q \cdot K^T$ и $A \cdot V$ направляются на цифровой массив **[SRAM-dIMC](../SRAM-dIMC.md)**.
   * Нелинейная операция $\text{Softmax}(X) = \frac{\exp(X_i)}{\sum \exp(X_j)}$ автоматически отчуждается и передается на векторные ядра **[RISC-V-Vector-Extensions](../RISC-V-Vector-Extensions.md)**.
2. **Оптимизация потока данных через Triton:**
   * Использование [Triton-Compiler](../Triton-Compiler.md) для генерации кода с совместным размещением (Data Co-location). Векторный блок RISC-V считывает результаты вычислений $Q \cdot K^T$ непосредственно из выходных регистров АЦП CiM-матрицы через локальную SRAM-буферную шину, минуя глобальный интерконнект.
3. **Результат:** Задержка выполнения блока MLA снижается на $78\%$ по сравнению с последовательной эмуляцией на CPU, а CUDA-библиотеки не используются вовсе.
{% endhint %}

### Кейс 3: Управление тепловыделением и межкристальным интерконнектом в 3D-Чиплетах

> **Сценарий:** При 3D-стекинге (3D-dIMC) логический кристал [RISC-V](../RISC-V.md) расположен под массивом памяти [SRAM-dIMC](../SRAM-dIMC.md). При пиковой нагрузке локальный перегрев (Hotspot) вычислительного ядра до $+105^\circ\text{C}$ вызывает деградацию временных задержек (Timing Violation) на шине D2D [UCIe](../UCIe.md).
> 
> **Вопрос:** Как ликвидировать физический перегрев на уровне архитектуры компоновки TRL 5?

{% hint style="success" %}
**Инженерное решение**
1. **Переход от 3D к 2.5D/3D-Гибридной топологии:**
   * Горячие вычислительные ядра [RISC-V](../RISC-V.md) выносятся на периферию кремниевого интерпозера (Silicon Interposer), а над массивом памяти размещаются только низкопотребляющие контроллеры управления.
2. **Термоизолирующие сквозные кремниевые отверстия (Thermal TSV):**
   * Внедрение массива неактивных сквозных отверстий (Dummy Thermal TSVs), исполняющих роль теплоотводящих мостов от нижнего кристалла к верхнему медному хладопроводу.
3. **Динамическое управление частотой и напряжением (DVFS):**
   * Интеграция внутрикристальных датчиков температуры, соединенных с аппаратным прерыванием ядра RISC-V. При превышении порога $+85^\circ\text{C}$ компиляторная среда исполнения (Runtime) автоматически перенаправляет поток векторных инструкций на менее загруженный соседний чиплет через шину [BoW](../BoW.md)/[UCIe](../UCIe.md).
{% endhint %}

## 7. Связанные понятия и терминологический граф

* [Compute-in-Memory](../Compute-in-Memory.md) — Технология вычислений непосредственно внутри массивов памяти.
* [RISC-V-Vector-Extensions](../RISC-V-Vector-Extensions.md) — Открытый стандарт векторных инструкций для архитектуры RISC-V.
* [Triton-Compiler](../Triton-Compiler.md) — Язык и компилятор с открытым исходным кодом для создания высокопроизводительных ИИ-ядер.
* [MLIR](../MLIR.md) — Инфраструктура промежуточных представлений для построения компиляторов.
* [Chiplet-Design](../Chiplet-Design.md) — Технология создания процессоров из отдельных специализированных кристаллов.
* [SRAM-dIMC](../SRAM-dIMC.md) — Цифровой Compute-in-Memory на базе статическои памяти SRAM.
* [ReRAM](../ReRAM.md) — Резистивная память с произвольным доступом на базе мемристорных эффектов.
* [MoE-Architecture](../MoE-Architecture.md) — Архитектура нейросетей «Смешение экспертов» (Mixture-of-Experts).
* [Spiking-Neural-Networks](../Spiking-Neural-Networks.md) — Спайковые импульсные нейронные сети третьего поколения.
* [UCIe](../UCIe.md) — Открытый стандарт межкристального интерфейса (Die-to-Die).
* [ASML-EUV](../ASML-EUV.md) — Фотолитографическое оборудование для ультрафиолетовой литографии.
* [HBM3e](../HBM3e.md) — Высокоскоростная стековая память с широкой шиной доступа.
* [Memory-Wall](../Memory-Wall.md) — Проблема диспропорции между скоростью процессора и пропускной способностью памяти.
* [Multi-head-Latent-Attention](../Multi-head-Latent-Attention.md) — Архитектура эффективного внимания с низким объемом KV-кеша.
* [DUV-Multi-Patterning](../DUV-Multi-Patterning.md) — Методы многократной экспозиции на глубоком ультрафиолете для снижения техпроцесса.
* [CoWoS](../CoWoS.md) — Проприетарная технология 2.5D/3D упаковки кристаллов от TSMC.
* [NVIDIA CUDA](../NVIDIA%20CUDA.md) — Проприетарная программно-аппаратная платформа вычислений на GPU.
* [CANN](../CANN.md) — Архитектура гетерогенных вычислений от Huawei.
* [MindSpore](../MindSpore.md) — Открытый фреймворк машинного обучения.
* [MXFP6/MXFP4](../MXFP6/MXFP4.md) — Микромасштабируемые форматы представления чисел низкой точности.
